🤖 CaveBot — Architecture

Three co-operating background services · Dual-mode input router · JSON script system

🤖 CaveBotService ORCHESTRATOR
Waypoint walk orchestrator. Loads a scripted path from disk, walks each waypoint by clicking coordinates on the minimap, then waits while companions handle attack and looting. Loops back to waypoint 1 when the path is complete.
script_name str
stand_seconds int
walking_enabled bool
monsters_to_attack [str]
sqm_positions [(int,int)]
map_region (x,y,w,h)
battle_list_x int
skill_key str
follow_mode bool
attack_mode str
1 Walk to waypoint → minimap click
2 Stand still N seconds
3 Attack window ← ChaseTarget
4 Loot corpses 2× ← AutoLooter
5 Advance → next waypoint
auto-starts companions

🎯 ChaseTargetService WORKER
Continuous battle-list scanner. Cycles through configured monster names, presses the attack key, and clicks the battle list to re-target. Repeats every scan_interval_ms.

💰 AutoLooterService WORKER
Background corpse looter. Right-clicks all configured SQM positions around the character. Runs continuously or on-demand via loot_once().

🔌 InputRouter INFRASTRUCTURE
Dual-mode input abstraction. Every mouse click and key press from every service passes through the InputRouter. The active mode is read from runtime.state.input_mode and can be changed at runtime.
